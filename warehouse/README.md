# Warehouse

Ingest, raw data store, rule packs, and the published contract surface. Run through Postgres.

## Quick start

```
uv sync --all-packages                 # .venv, every workspace member, the dev group
uv run warehouse db start              # local Postgres, no root required
uv run warehouse db upgrade            # migrations, ending in a views rebuild
uv run warehouse rules load            # rule_packs/*.toml -> core.rule_pack*
uv run pytest -m ""                    # every tier, including the ones needing a database
```

## Command surface

| Command | Does |
| --- | --- |
| `db start` / `stop` | Local Postgres, no root |
| `db upgrade` / `downgrade` / `rebuild-views` | Migrations, each ending in a views rebuild |
| `db current` / `revision` | The applied head, and a new autogenerated migration |
| `rules check` / `load` / `generate` | Parse packs, load them, generate components from the OpenAPI document |
| `ingest event` / `region` / `season-events` / `season-teams` | FTC Events, per event or per season |
| `ingest breakdowns` | Component-level history from FTC Events `/scores`, resumable |
| `ingest awards` | Awards from FTC Events, one call per event |
| `ingest status` | Cursor health, through `pub.v_ingest_cursor` |
| `ingest backfill` | Worldwide match history from FTCScout |
| `ingest scout-awards` | Worldwide awards from FTCScout, one call per season |
| `ingest alliance-roles` | Playoff alliance roles from FTCScout, updating slots that already exist |
| `derive opr` | Solve the OPR baseline from match data into `derived.team_event_opr` |
| `ops fit-runs` | Every fit run, with its versions, scope, timestamps and rating-row count |
| `ops drop-model-version` | Delete a version's runs and, by cascade, its ratings |
| `config` | What the process resolved: database URL, payload root, whether credentials are set |

## Schemas

| Schema | Holds |
| --- | --- |
| `raw` | Payload provenance: hashes, ingest runs, cursors, conflicts, diffs |
| `core` | The organized data: seasons, events, teams, matches, breakdowns, rankings, awards, advancement |
| `derived` | Computed output: fit runs, OPR, EPA and pRidge ratings |
| `pub` | Public views |

Views are the contract and base tables are private. Reads go through `pub`.

## Layout

```
src/warehouse/
  schema/      SQLAlchemy metadata: raw, core, derived
  ingest/      FTC Events and FTCScout clients, payload store, cursors, transforms, writers
  rules/       rule-pack model, loader, OpenAPI generator
  derive/      computed quantities
  client.py    the typed read and write surface the models use
  ops.py       fit-run inspection and version retirement
views/         *.sql, dropped and re-run in full by every migration
rule_packs/    *.toml, the source of truth for a season; the table is the read surface
migrations/    Alembic, one linear history
docs/          data sources and a psql guide
tests/         fixtures are synthetic, generated from real distributions
```

### Local Postgres

`db start` uses `pgserver`, which ships Postgres binaries as a wheel, so the host needs no system Postgres and no
root. Anything that speaks the Postgres network protocol works instead.

### Credentials

Reading from FTC Events needs your own.

```
export WAREHOUSE_FTC_EVENTS_USERNAME=...
export WAREHOUSE_FTC_EVENTS_TOKEN=...
uv run warehouse ingest event 2025 USPACMP      # one event, every endpoint
uv run warehouse ingest region 2025 --limit 3   # one region, a few events
uv run pytest -m credentialed                   # check all endpoints
```

## Roles

The database owner is the only writer. `ftc_readonly` is a NOLOGIN role holding USAGE and SELECT on `pub` and
nothing else; a person gets a login role of their own and is granted it.

## Payload store

Payload bodies live outside the database, gzipped under `var/payloads` and named for the SHA-256 of the response
bytes. `raw.payload` keeps the hash and the path.

## Migrations

The warehouse owns all DDL, model output tables included, in one Alembic history with one version counter. Every
migration ends by dropping every view and re-running `views/` from scratch. Files apply in filename order, and the
numeric prefix is the dependency order. The per-season `v_breakdown_<season>` views are generated after the static
files, from `core.rule_pack_component`, with a `v_phase_points_<season>` beside each that sums the season's leaves into
auto and teleop.
